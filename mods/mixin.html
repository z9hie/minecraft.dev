Mixin — что это и зачем

Mixin — это механизм, через который моды меняют код Minecraft, не имея доступа к его исходникам. Без Mixin не было бы ни одного серьёзного мода. Разбираем как он работает.

Представь: у тебя есть Minecraft в виде скомпилированного .jar-файла. Ты не можешь открыть его, изменить пару строк и сохранить обратно. Но тебе нужно, чтобы игра делала что-то по-другому. Как быть?

Вот тут и приходит Mixin. Это система, которая позволяет «вклиниться» в выполнение методов Minecraft и добавить свой код. Не переписать метод, а именно вставить свой код в нужное место.

1. Аналогия

Представь что Minecraft — это повар, который готовит блюдо по рецепту. Рецепт ты не можешь изменить. Но у тебя есть возможность встать рядом и:

  • Inject (впрыск) — сказать «стоп, перед тем как добавить соль, положи ещё перец»
  • Redirect (перенаправление) — сказать «вместо соли используй сахар»
  • Overwrite (перезапись) — сказать «делай всё то же, но вместо последнего шага сделай вот это»
  • ModifyVariable (изменение переменной) — сказать «когда возьмёшь 3 яйца, возьми 5»

Это всё — разные типы Mixin. Для TargetHUD и большинства визуалов используется Inject и Redirect.

2. Простой пример

Допустим, мы хотим чтобы игра писала в лог каждый раз, когда игрок получает урон. У Minecraft есть класс PlayerEntity с методом damage(). Мы не можем его открыть и изменить. Но можем сделать миксин:

java 
package com.example.myfirstmod.mixin;

import net.minecraft.entity.player.PlayerEntity;
import org.spongepowered.asm.mixin.Mixin;
import org.spongepowered.asm.mixin.injection.Inject;
import org.spongepowered.asm.mixin.injection.callback.CallbackInfo;
import org.spongepowered.asm.mixin.injection.At;

@Mixin(PlayerEntity.class)
public class PlayerEntityMixin {

    @Inject(method = "damage", at = @At("HEAD"))
    private void onDamage(CallbackInfo ci) {
        System.out.println("Игрок получил урон!");
    }
}

Что здесь происходит:

  • @Mixin(PlayerEntity.class) — говорим Mixin, что мы «прицепимся» к классу PlayerEntity
  • @Inject(method = "damage", ...) — говорим что вклиниваемся в метод damage()
  • at = @At("HEAD") — «в самом начале метода, до того как Minecraft что-либо сделает»
  • CallbackInfo ci — параметр, через который можно отменить выполнение метода (если нужно)

Теперь каждый раз, когда игрок получает урон, в консоль будет писаться «Игрок получил урон!». Мы не меняли код Minecraft, но добавили в него своё поведение.

3. Точки впрыска (At)

@At определяет, в какое именно место метода мы вклиниваемся. Основные варианты:

  • @At("HEAD") — в самое начало метода
  • @At("RETURN") — перед каждым return
  • @At("TAIL") — в конце, после последнего return
  • @At(value = "INVOKE", target = "...") — перед вызовом конкретного метода
  • @At(value = "FIELD", target = "...") — при доступе к полю класса

Для TargetHUD, например, нам нужно вклиниваться в метод отрисовки HUD — там @At("HEAD") даёт нам точку, где мы можем нарисовать свой интерфейс поверх.

4. Регистрация миксина

Недостаточно просто написать класс с @Mixin. Нужно сказать Fabric, что такой миксин существует. Это делается в файле myfirstmod.mixins.json:

json 
{
  "required": true,
  "package": "com.example.myfirstmod.mixin",
  "compatibilityLevel": "JAVA_21",
  "minVersion": "0.8",
  "mixins": [
    "PlayerEntityMixin"
  ],
  "client": [],
  "injectors": {
    "defaultRequire": 1
  }
}

Ключевое — массив mixins. Каждый новый миксин-класс нужно добавить туда по имени. Если класс называется PlayerEntityMixin и лежит в пакете com.example.myfirstmod.mixin, в массив пишем "PlayerEntityMixin".

Если миксин не заработал — в 90% случаев ты забыл добавить его в mixins.json. Mixin не подхватывает классы автоматически, их нужно регистрировать руками.

5. Частые ошибки

Mixin apply failed

Значит, ты вклиниваешься туда, куда нельзя — например, в метод которого нет или с неправильной сигнатурой. Проверь method = "...": имя должно точно совпадать с методом в Minecraft.

Crash на запуске

Скорее всего, @Mixin(SomeClass.class) ссылается на класс, которого нет в этой версии Minecraft. Или метод вызывается с неправильными параметрами.

Миксин применяется, но ничего не делает

Проверь точку впрыска. Если метод не вызывается в нужный момент — твой код тоже не выполнится. Например, вклиниваться в render() бесполезно, если ты хочешь ловить момент урона.

6. Как узнать что за метод

Главная проблема новичка — непонятно, куда вклиниваться. Ты знаешь что хочешь «поймать момент когда игрок получает урон», но не знаешь какой метод за это отвечает.

Решения:

  • Смотри исходники Minecraft. В IntelliJ есть кнопка genSources в панели Gradle — она скачивает декомпилированные исходники игры, которые можно читать как обычный Java-код
  • Ищи похожие моды на GitHub. Если хочешь TargetHUD — открой репозиторий мода с TargetHUD и посмотри, в какие методы он вклинивается
  • Читай логи. Если миксин не применился, Minecraft напишет об этом в лог с указанием класса и метода
genSources — самая полезная команда для разработчика модов. В панели Gradle справа: Tasks → fabric → genSources. После этого все классы Minecraft станут доступны для чтения.
